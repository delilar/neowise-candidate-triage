# Тестовое Neowise. AI-помощник для входящих заявок

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`.

Страница по умолчанию включает **учебный каталог**: четыре товара, цены, остатки, доставка и оплата. Кнопки примеров заполняют заявку; раздел «Товары и условия для проверки» показывает базу. Снимите флажок «Использовать учебный каталог», чтобы проверить исходный имитатор.

Это локальное демо retrieval + шаблонный генератор, **без внешней LLM и эмбеддингов**. Сведения ищутся по названиям, артикулам и категориям; черновик содержит использованные источники. Подробности задачи, примеры и ограничения: [docs/DEMO.md](docs/DEMO.md).

## Тесты

В каталоге проекта выполните:

```sh
node --test
```

Не нужны `npm install`, внешние сервисы и API-ключи. Проверено на Node.js 22.22.0: 68 тестов прошли.

- `test/api.test.mjs` поднимает настоящий HTTP-сервер на свободном локальном порту: проверяет неверный ввод, три допустимые темы, все пять меток сбоя, структуру ответа, доступность сервера после ошибки. Дополнительно проверяет провайдера, игнорирующего отмену, и запрет подмены статуса ответа полями модели.
- `test/ui.test.mjs` исполняет обработчик из самой HTML-страницы с подставными DOM и fetch: успех → сбой, очистка старого черновика, пустой ввод, сетевой сбой/таймаут, HTTP-ошибка, битый JSON и повторная отправка во время ожидания. Это автоматические проверки логики интерфейса, без запуска браузера.
- `test/catalog.test.mjs` проверяет поиск товаров, цены и источники, отсутствие товара и неизвестную модель, условия оплаты и доставки, невозможность заменить цену инструкцией пользователя и сохранность всех пяти сценариев сбоя.

## Реализованное поведение

`POST /api/triage` принимает JSON вида `{"text":"Когда доставка?"}`.

Без `mode` API использует исходный имитатор. Для ответа по базе передайте `{"text":"Сколько стоит K1?","mode":"catalog"}`. Структура ответа остаётся прежней: `status`, `topic`, `draft`; список источников включён в текст черновика. Неизвестный режим возвращает 400. `GET /api/catalog` возвращает учебную базу, которую показывает страница. База читается при запуске; после редактирования `knowledge.json` перезапустите сервер.

| Ситуация | HTTP | Ответ |
| --- | --- | --- |
| Битый JSON, отсутствующий, нестроковый или пустой после `trim()` текст | 400 | `{"status":"invalid_input"}` |
| Допустимая тема и непустой строковый черновик | 200 | `{"status":"ready","topic":"delivery","draft":"…"}` |
| Ошибка, таймаут, битый JSON или неверная структура ответа модели | 200 | `{"status":"manual_review","topic":null,"draft":null}` |

Проверка результата AI находится в `triage()` в `server.mjs`: после разбора JSON проверяются объект, тема (`delivery`, `pricing`, `other`) и строковый черновик с непробельным содержимым. В ответ копируются только разрешённые поля. Статус задаёт сервер.

Ожидание AI ограничено 300 мс через `Promise.race`; при таймауте `AbortController` отменяет работу имитатора. Гонка завершит ожидание и для асинхронного провайдера, игнорирующего сигнал. Таймер очищается при любом исходе. Это предел асинхронного ожидания с учётом планировщика Node.js, а не способ прервать синхронный код, блокирующий поток. `mock-ai.mjs` не изменён.

Страница показывает название темы и черновик, напоминает проверить ответ перед отправкой. Старый результат очищается уже при новой отправке, а при сбое выводится сообщение «Нужен ручной разбор» и инструкция подготовить ответ самостоятельно. Исходная заявка остаётся в поле ввода. Кнопка блокируется до завершения запроса; отдельный сетевой таймаут страницы — 5 секунд. Вывод через `textContent` не исполняет HTML из ответа.

## Польза для менеджера

Менеджер быстрее получает тему и основу ответа, а при сбое сразу переходит к ручному разбору без риска скопировать черновик предыдущей заявки. Эффект можно измерить по медианному времени от открытия заявки до готового проверенного ответа, сравнив одинаковые типы заявок с помощником и без него; дополнительно отслеживать долю ручных разборов и ошибок в ответах. Ускорение пока не измерялось.

## Как проверить на странице

1. Введите «Когда доставка?» — появятся тема «Доставка» и черновик.
2. По очереди отправьте `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` — появится инструкция для ручного разбора, старый черновик исчезнет.
3. Отправьте пробелы — появится просьба ввести текст, запрос к API не отправится.
4. Снова отправьте обычный текст — помощник продолжит работать.

## Использование AI и границы проверки

Для реализации, тестов и документации использован OpenAI Codex. Проверки выполнены этим же AI-агентом: реально запущены исполнимые тесты, проверено отсутствие изменений имитатора относительно исходного коммита. Дополнительно в Chrome с настоящим сервером проверены три темы, все пять меток сбоя, пробельный ввод, очистка черновика и восстановление после ошибки; сценарий `[timeout]` завершился примерно за 320 мс. Это не независимое человеческое ревью. Проверить понимание решения можно по шагам выше и исходному коду.

Это локальный учебный пример: используется имитатор, реальные заявки и внешние AI-сервисы не подключены.

## Исходные требования задания

1. Доработайте `POST /api/triage`. Принимайте JSON с полем `text`, содержащим непустую строку. При пустом, отсутствующем, нестроковом вводе или битом JSON верните HTTP 400 и `{"status":"invalid_input"}`.
2. При корректном ответе модели верните HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`. Допустимые темы — `delivery`, `pricing`, `other`. Черновик должен быть непустой строкой. При таймауте, ошибке модели или неподходящем ответе верните HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Ограничьте ожидание модели 300 мс. Оставьте поведение выданного имитатора прежним.
3. Покажите на странице тему и черновик при успехе. Для `manual_review` покажите понятное сообщение менеджеру и очистите предыдущий черновик. Добавьте хотя бы один исполнимый тест для поведения при сбое и инструкцию его запуска.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.
